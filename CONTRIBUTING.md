# Contributing

Thank you for your interest in improving this account. To maintain high standards and velocity, please adhere to the following guidelines.

## Quick Start

1. **Fork and Clone**: Fork the repository and clone it locally.
2. **Environment Setup**: Run the bootstrap script or follow the installation steps in the project-specific `README.md`.
3. **Branching**: Create a feature branch using the format `feat/description` or `fix/description`.
4. **Implement**: Follow the [Coding Standards](docs/standards.md).
5. **Verify**: Run the test suite and linter.
6. **Submit**: Push your changes and open a Pull Request against the `master` branch.

## Contribution Process

### Issue Reporting
- Search for existing issues before opening a new one.
- Use the provided issue templates.
- Be precise: provide reproduction steps, expected vs. actual behavior, and environment details.

### Pull Requests
- **Atomic Changes**: Keep PRs focused on a single logical change.
- **Documentation**: Update accompanying documentation if the change affects usage or architecture.
- **Verification**: All PRs must pass CI checks.
- **Review**: Address all review comments before requesting a final merge.

## Standards
Refer to [docs/standards.md](docs/standards.md) for detailed coding and documentation requirements.
